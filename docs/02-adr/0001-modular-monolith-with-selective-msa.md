# ADR-0001: 모듈러 모놀리스 + 선택적 MSA
- 상태: Accepted · 날짜: 2026-11-05

## 맥락
도메인 5개(user, asset, point, cs, event) 중 event만 주 1~2회 수백 배 폭주한다. 나머지는 트래픽이 일정하고, point는 원장 정합성이 중요해 트랜잭션 경계가 넓다.

## 결정
user/asset/point/cs는 **하나의 모듈러 모놀리스**로, event만 **독립 서비스(MSA)** 로 분리한다. 둘 사이 원장 반영은 Kafka 비동기로 한다.

## 고려한 대안
| 대안 | 장점 | 단점 | 기각 이유 |
|---|---|---|---|
| 전체 MSA (5개 서비스) | 도메인별 독립 배포/확장 | 네트워크 홉, 분산 트랜잭션, 운영 비용 5배 | 확장이 필요한 건 event뿐 |
| 단일 모놀리스 | 가장 단순 | 이벤트 피크 시 전체를 확장해야 함, 장애 전파 | 비용·격리 실패 |
| **모놀리스 + event MSA** | 필요한 곳만 탄력 확장, 장애 격리 | 두 배포 단위 간 계약 관리 필요 | **채택** |

## 결과
- (+) 이벤트 장애가 로그인/잔액 조회로 번지지 않는다.
- (+) DR 시 "모놀리스만 복구"라는 선택적 복구가 자연스럽게 가능 (ADR-0004).
- (−) 원장 반영이 최종 일관성 → 사용자에게 "지급 예정" UX 필요.
- 후속: ArchUnit으로 모듈 경계 강제.
