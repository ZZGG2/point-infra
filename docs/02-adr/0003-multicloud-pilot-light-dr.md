# ADR-0003: 멀티클라우드 Pilot Light DR (GCP)
- 상태: Accepted · 날짜: 2026-11-05

## 맥락
금융 서비스는 리전/클라우드 사업자 수준 장애에도 핵심 업무를 이어가야 한다. 그러나 1:1 Active-Active는 평시 2배 비용과 양방향 데이터 동기화 복잡도가 크다.

## 결정
**AWS를 Main(100%)** 으로, **GCP를 Pilot Light DR** 로 둔다. 평시 GCP에는 **DB(Cloud SQL)와 네트워크만** 상시 유지하고, 컴퓨팅(GKE)은 장애 시 Terraform으로 생성한다.

## DR 전략 비교
| 전략 | RTO | RPO | 평시 DR 비용 | 복잡도 |
|---|---|---|---|---|
| Backup & Restore | 수 시간~일 | 수 시간 (백업 주기) | 매우 낮음 | 낮음 |
| **Pilot Light** | **수십 분** | **초 단위 (CDC)** | **낮음 (DB만)** | 중간 |
| Warm Standby | 수 분 | 초 단위 | 중간 (축소 클러스터 상시) | 중간 |
| Active-Active | ~0 | ~0 | 높음 (2배) | 매우 높음 (양방향 충돌) |

## 왜 같은 AWS의 다른 리전이 아닌 GCP인가
| 관점 | AWS 타 리전 | GCP |
|---|---|---|
| 리전 장애 대응 | ✅ | ✅ |
| 사업자 수준 장애 (IAM, 글로벌 컨트롤 플레인) | ❌ 공동 운명 | ✅ |
| 벤더 종속 탈피 / 협상력 | ❌ | ✅ |
| 구현 난이도 | 낮음 | 높음 (네트워크, IAM, 이미지, 상태 분리) |
| 포트폴리오 가치 (MSP 멀티클라우드 역량) | 보통 | 높음 |

## 결과
- (+) 평시 DR 비용 = Cloud SQL + VPN + 소량 스토리지
- (−) RTO가 Warm Standby보다 김 (GKE 생성 ~10~15분) → 30분 목표 내 수용
- (−) 이미지, 시크릿, State를 GCP 쪽에도 유지해야 함 → ADR-0010
