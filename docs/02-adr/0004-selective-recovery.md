# ADR-0004: DR 시 선택적 복구 (모놀리스만)
- 상태: Accepted · 날짜: 2026-11-05

## 맥락
DR 환경에 이벤트 MSA까지 띄우면 Redis, Kafka, 대규모 노드 풀까지 필요해 RTO와 비용이 모두 커진다. 그러나 이벤트는 연기해도 고객 손실이 거의 없다.

## 결정
DR 시 **monolith(user, asset, point, cs)만** 복구한다. `/api/events/**`는 Ingress 단에서 **503 + 점검 안내**를 반환한다.

## 우선순위 근거
| 기능 | 중단 시 영향 | DR 복구 |
|---|---|---|
| 로그인 | 모든 기능 불가 | ✅ |
| 포인트 잔액/내역 조회 | 고객 불안, 민원 | ✅ |
| 포인트 사용/환불 | 금전 피해 | ✅ |
| 자산 조회 | 불편 | ✅ (monolith에 포함되어 비용 0) |
| 이벤트 참여 | 이벤트 연기로 대체 가능 | ❌ |

## 결과
- (+) DR 노드 수 최소화 → GKE 생성 + 배포 시간 단축 (RTO 기여)
- (+) DR 환경에 Redis/Kafka 불필요
- (−) 장애 중 진행 중이던 이벤트의 미반영 당첨 건은 Failback 후 대사·재처리 필요 → DR 런북에 포함
