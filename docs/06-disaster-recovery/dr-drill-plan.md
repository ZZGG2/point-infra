# DR 훈련 계획

## 1. 훈련 유형

| 유형 | 주기 | 방법 | 운영 영향 |
|---|---|---|---|
| Tabletop | 분기 | 런북 읽으며 단계별 담당·판단 점검 | 없음 |
| 부분 훈련 (Compute) | 월 1회 | `gcp-dr-compute` apply → monolith 기동 → Cloud SQL **읽기 복제본/클론**에 연결 → destroy | 없음 (DNS 미전환) |
| 전체 훈련 (Full Failover) | 프로젝트 중 2회 | AWS 측 ALB Health Check 강제 실패 → 전 과정 수행 → Failback | 점검 공지 필요 |

> 부분 훈련에서 실 Cloud SQL을 승격하면 복제가 깨지므로, **클론 인스턴스**를 만들어 연결한다.

## 2. 장애 주입 방법 (리전 장애 시뮬레이션)

| 방법 | 재현되는 상황 |
|---|---|
| Route 53 Health Check 대상 경로를 실패시키기 (Inverted) | 트래픽 관점 리전 장애 |
| EKS 노드그룹 0 + ALB 리스너 삭제 | 컴퓨팅 장애 |
| AWS FIS로 Aurora Failover / 네트워크 차단 | 부분 장애 |
| AWS 측 VPN 연결 비활성화 | 복제 경로 단절 → RPO 측정 |

## 3. 측정 항목 & 결과 기록

| 회차 | 날짜 | 유형 | 승인→Ready | DNS 전환 | **RTO** | **RPO** | 이슈 | 개선 |
|---|---|---|---|---|---|---|---|---|
| #1 | | 부분 | | - | | - | | |
| #2 | | 전체 | | | | | | |
| #3 | | 전체 (개선 후) | | | | | | |

**포트폴리오 산출물:** 회차별 RTO 단축 그래프, 워크플로 실행 화면, Grafana CDC Lag 캡처.

## 4. 성공 기준
- RTO ≤ 30분, RPO ≤ 5초
- 스모크 테스트 100% 통과
- 원장 대사 불일치 0건 (Failback 후)
- 수동 콘솔 작업 0회
